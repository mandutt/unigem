## D-0. 승인과 결정 기록

1. 이 문서는 사용자가 직접 지시로 전달한 것이다. `decisions.md`에 전달 일시, 문서 SHA256, 아래 결정을 기록한다.
2. **CP-C1(F2 방향) 결정:**
   - **F2의 제품 경로는 기존 운영 ASR(komixv2, whisper-turbo)을 그대로 쓴다.** 인제스트 라우팅을 변경하지 않는다.
   - **D(EG2 위 자체 reader 학습)는 사전 선언한 연구 트랙**으로 진행한다(D-5). D가 15%(G-C2)를 통과해도 제품 채택은 F2의 역할 정의(D-4, D0-b)에 따라 사용자가 결정한다.
   - Notesoop의 G-C2는 **FAIL 유지**(FLEURS ko CER 18.96%). komixv2(5.49%), whisper-turbo(5.09%)가 제품 경로로서 G-C2 기준을 충족함을 기록한다.
3. **게이트 승인:** G-C2a를 **승인**(Q8 특징 사용 시 CER 상대 변화 −0.12%, 기준 ≤ +10% 충족). G-A3S는 평균 코사인(0.999642)만 보고되었으므로 **프레임별 최소값과 하위 분위수(p1, p5)를 보고서에 추가**해 판정한다.
4. **불허·보류:** D-γ(운영 그래프에 LoRA merge)는 **불허**. D-γ′(LoRA 사본)는 **보류**, D-5의 결과와 비용 견적 후 재승인. D-δ(komixv2 pseudo-label 증류)는 **보류**.
5. **VPS 운영 방침:** VPS 5대는 **무료 연산 자원이므로 가능한 한 작업을 분배**한다. 단 plan §3.2, §8, Addendum A·B·C의 제약(P0 전용, 판정은 로컬, 호스트당 무거운 job 1개, 디스크 가드)은 그대로 적용한다. 작업이 끝나면 데이터·캐시를 정리하고 **정지**한다(별도 지시 전까지).
6. 사용자가 이 문서의 특정 항목을 거부하면 그 항목은 무효이며 기존 기준이 유지된다.

## D-2. 분산 실행 원칙 (VPS 활용 확대)

1. **병렬화 단위는 "독립 실험(arm)"이다.** VPS 간 네트워크로 한 학습을 쪼개는 분산 학습은 하지 않는다. 한 호스트가 하나의 arm을 끝까지 수행한다.
2. **연산 중복 허용.** 연산이 무료이므로 같은 오디오에 대한 특징 추출을 호스트마다 반복해도 된다(arm별 저장 특징이 다르므로 디스크는 분리). 중복 때문에 일정이 늘어나지 않게 한다.
3. **디스크가 병목이다(호스트당 20GB).** 다음을 지킨다.
   - 데이터 예산 = (실측 `df` 여유 − 2GB 가드 − venv·모델·로그). D0-c에서 호스트별로 확정한다.
   - 한 파일럿의 모든 arm은 **같은 오디오 목록**을 쓴다. 시간 H는 가장 큰 특징(arm F-C, 약 0.74GB/h)이 호스트 데이터 예산의 70% 이하가 되도록 **4h ≤ H ≤ 6h**에서 정한다.
   - 큰 특징 캐시는 학습이 끝나면 삭제하고 체크포인트·지표·로그만 로컬로 회수한다(Wave 2에서 같은 호스트가 재사용할 경우만 유지).
4. **재현성:** 모든 호스트가 같은 코드 커밋, 같은 venv lock, 같은 모델 revision·해시, 같은 시드·하이퍼파라미터를 쓴다. 학습 스레드 수는 4로 고정한다. 호스트 편차는 정확도(CER)에는 영향이 없고 소요 시간에만 영향이 있다고 가정하되, **교차 호스트 재현 복제(D-5.7)**로 확인한다.
5. **성능 판정 규칙 유지:** 지연·RAM·RTF는 로컬 측정만 판정에 쓴다. VPS 값은 "참고(VPS)". 정확도(CER, 정밀도 등)는 하드웨어와 무관하므로 VPS 결과로 판정할 수 있다.
6. **데이터 등급:** VPS에는 **P0만** 올린다. AI Hub 유래 데이터는 사용자 확인(약관 문제 없음)에 따라 VPS에서 쓸 수 있으며 매니페스트에 이용 조건 확인 표시를 유지한다. P1(메모리 문장, 사용자 미디어, 실제 입력 오타)은 로컬 전용.
7. **자원 상한:** job마다 타임아웃과 메모리 상한(cgroup 가능 시)을 건다. OOM·hang은 1회 기록 후 보고하고 중단한다(plan §0-5). 각 job은 체크포인트에서 재개할 수 있어야 한다.

## D-3. 프로세스 규칙 추가 (AM-9, AM-10)

### AM-9: 평가 세트 사용 규칙
- **중간 의사결정(arm 선택, 조기 종료, 중단 판단)에는 dev 세트만** 쓴다(FLEURS ko dev, AI Hub 유래 holdout).
- **test 세트(FLEURS ko test, Zeroth test, Kspon eval_clean)는 최종 판정에 1회만** 쓴다. 이미 이번 라운드에서 사용한 test(G-C2 측정)는 사용된 것으로 기록하고, D 트랙의 최종 test 1회는 새로 선언한다.
- 위반 시 해당 test 결과는 "탐색적"으로 표기하고 게이트 판정에 쓰지 않는다.

### AM-10: 병렬 arm 실험 규칙
- arm 간 **코드, 하이퍼파라미터, 시드, 데이터 목록을 동일**하게 한다. 달라도 되는 것은 입력 특징의 종류·차원뿐이다. arm별 튜닝 금지.
- 모든 arm의 결과를 보고한다(성공한 arm만 보고 금지). 실패·불수렴·중단 사유도 기록한다.
- arm 선정은 사전 선언한 지표(D-5.6)로만 한다.

## D-4. F2 역할 정의에 관한 기준 (CP-D1 결정 준비)

- F2의 제품 가치는 "정확도 대체"가 아니라 **"별도 런타임 없이 상주 EG2로 즉시 만드는 저비용 초벌 전사"**일 때만 성립한다. D가 15%를 통과해도 komixv2(5.49%)보다 약 3배 오류가 많다.
- 이 역할이 충분한지는 **다운스트림 지표(D0-b)**로 판단 근거를 만든다. 사용자는 CP-D1에서 (a) D를 제품 초벌 레인으로 채택, (b) 연구 트랙으로만 유지, (c) 중단 중 하나를 고른다.
- 이 문서는 어느 쪽도 사전 결정하지 않는다.

## D-5. D-β 파일럿 (EG2 오디오 특징 위 reader, 4개 arm × VPS 병렬)

### D-5.1 목적
다음 구조 가설을 **학습 비용이 작은 파일럿으로 검증**한다.
> Notesoop의 성능 상한은 "LM 24층 → 대조학습 projection → 256차원 L2" 병목에서 오며, 타워 중간층을 직접 읽으면 같은 reader로 CER이 의미 있게 낮아진다.

### D-5.2 사전 조건
- D0-a(정규화 통일), D0-c(VPS 점검), D0-d(비용 probe), D0-e(그래프 출력 확인)가 완료되어야 한다.
- 외부 사례(arXiv 2610.28673 등)는 **독립 확인 전에는 근거로 쓰지 않는다.** 논문 원문에서 사용 모델, 학습 하드웨어, 데이터 시간을 확인해 보고서에 기록한다.

### D-5.3 데이터 (P0, 모든 arm이 같은 오디오)
- **학습 H시간(4~6h):** 낭독체 약 65% + 대화체 약 35%. 소스는 로컬에 있는 AI Hub 음성 중에서 Hermes가 선택하고(Zeroth train 등 공개 낭독체 포함 가능) 소스별 시간·화자 수를 보고한다.
- **dev 세트(중간 판단 전용):** (1) **FLEURS ko dev 전체**(주 dev), (2) 낭독체 holdout(화자 분리), (3) 대화체 holdout(화자 분리).
- **절대 학습에 쓰지 않는 것:** FLEURS test, Zeroth test, Kspon eval_clean 100, 사용자 미디어.
- 오디오 목록은 매니페스트(경로, 시간, 소스, 화자, SHA256)로 고정하고 호스트로 **FLAC로 전송**한다(대역폭 먼저 측정). 공개 세트(FLEURS, Zeroth)는 호스트가 직접 받아도 된다.
- 참조 텍스트에는 D0-a에서 통일한 정규화를 적용한다(숫자·영문 처리 포함).

### D-5.4 arm 구성

| Arm | 입력 특징 | 차원 | 저장량(대략) | 가설 |
|---|---|---|---|---|
| **F-D (대조군)** | Notesoop 방식 256차원 특징(타워 → LM → norm → projection[:256] → L2) | 256 | 약 0.05GB/h | 병목 상태의 기준선 |
| **F-A** | 타워 최종 출력 `audio_features` (LM 이전) | 512 | 약 0.09GB/h | LM·projection 병목 제거 효과 |
| **F-B** | 타워 11층 hidden 1개 | 1024 | 약 0.18GB/h | 단일 상위층 |
| **F-C** | 타워 6/8/10/11층 hidden의 학습 가중 혼합 | 1024 × 4 | 약 0.74GB/h | 다층 혼합 효과 |

- 특징 출처: A2 Q8 다층 그래프(`eg2_audio_q8_layers.onnx`, 12층 hidden)를 우선 사용한다(배포 그래프 계열, Q8 특징 안전성은 G-C2a로 확인). 출력이 부족하면 연구용 FP32 그래프를 쓰고 이후 Q8 parity를 확인한다.
- **F-D 특징은 로컬에서 추출**(Notesoop 파이프라인, 약 H × 0.09시간)해 호스트로 전송한다(총 0.3GB 이하).
- 모든 층 입력은 층별 LayerNorm 후 사용하고, 다층 arm(F-C)은 소프트맥스 가중 합(층 가중치 학습) 후 선형 투영한다.

### D-5.5 reader 사양과 학습 (모든 arm 동일)
- 구조: 입력 투영(→ d=384) → Transformer 4층(6 head, ff 1536) → CTC 헤드. 총 학습 파라미터 **≤ 10M**. 프레임률 25Hz 유지.
- 출력 단위(CTC): 학습 전사에서 3회 이상 등장한 한글 음절 + 숫자 0~9 + 라틴 소문자 + 공백 + `<unk>`. **dev 참조 텍스트 문자의 어휘 포함율(CER 하한)**을 반드시 보고한다.
- 최적화: AdamW, 최대 학습률 1e-3(웜업 후 코사인 감쇠), 기울기 클리핑 1.0, 특징 수준 마스킹(시간 마스크 2회 × ≤10프레임, 특징 드롭아웃 0.1). 길이 정렬 배치.
- 종료: **FLEURS dev CER(공백 무시) 기준 조기 종료(인내 5 에폭)**, 호스트당 최대 48시간. 체크포인트는 시간 단위로 저장.
- 시드 1(파일럿). 가능하면 두 번째 시드는 Wave 2에서 승자 arm에 대해서만.

### D-5.6 지표와 사전 선언 판정 (제안값, 이 문서 전달로 등록)

**보고 지표(모든 arm, dev 3종):** CER(공백 무시, 주지표), CER(공백 포함), WER, 학습 파라미터 수, 에폭당 시간, 총 학습 시간, 어휘 포함율, 오류 유형(숫자·영문·띄어쓰기별 오류 수).

**선정:** F-A, F-B, F-C 중 **FLEURS dev CER(공백 무시)이 가장 낮은 arm**을 `best`로 한다.

**R-D1 (병목 가설):** 상대 개선 = (CER_{F-D} − CER_{best}) / CER_{F-D}, 문장 단위 **대응 부트스트랩 95%** 구간.
- **지지:** 상대 개선 ≥ **20%**이고 구간 하한 > 0.
- **INCONCLUSIVE:** 10% ≤ 상대 개선 < 20%, 또는 하한 ≤ 0. **1회만** 확장(시간 2배 또는 시드 반복) 허용.
- **기각:** 상대 개선 < 10% → **D 중단 권고**(F2는 기존 경로 유지).

**R-D2 (규모 전망):** `best` arm의 학습 곡선(H/3, 2H/3, H 시간 학습)을 로그-시간에 선형 적합해 **40시간 외삽 FLEURS dev CER**과 예측 구간을 보고한다.
- 외삽 점추정 ≤ 15%이면 스케일업 권고, 15% 초과이면 중단 또는 보류 권고. 외삽의 불확실성(구간)을 반드시 함께 제시한다.
- 곡선 실행은 `best` arm이 정해진 뒤 Wave 2에서 서로 다른 호스트에 H/3, 2H/3 학습을 병렬 배치한다.

**비용 규칙(사전 선언):** D0-d의 timing probe로 산출한 (에폭당 시간 × 계획 에폭 수)가 호스트당 48시간을 넘으면, 에폭 수·reader 크기·프레임률(12.5Hz 옵션)을 줄여 사양을 조정하고 **조정 내용을 보고서에 기록**한다. 일정 때문에 평가 절차를 줄이지 않는다.

### D-5.7 교차 호스트 재현 복제
- `best` arm 또는 F-B를 **다른 VPS 1대에서 같은 시드로 복제 학습**해 dev CER 차이가 ±0.5%p(절대) 이내인지 확인한다(Wave 2 또는 Wave 1의 여유 호스트).
- 초과하면 비결정성 원인을 보고하고, 이후 판정에는 시드 평균을 쓴다.

### D-5.8 해석 지침 (결과 → 의미)

| 결과 | 해석 |
|---|---|
| F-A ≫ F-D | LM·projection 병목이 원인. 타워 출력(LM 이전)만 읽으면 충분 → **가장 단순한 구조** |
| F-B/F-C ≫ F-A | 중간층 정보가 필요. 다층 탭 확보 필요(D0-e) |

| 모든 arm이 높고 어휘 포함율 낮음 | 출력 단위 설계 문제 → 단위 재설계 후 재측정(1회) |

## D-6. A1 파일럿 (F5 + F6 + F4 정상 identity, LoRA)

G-DATA 1단계가 PASS이므로(F5 2,000쌍, F6 1,320쌍) 파일럿을 시작한다. **2단계 확장은 요청하지 않는다.**

### D-6.1 timing/memory probe (최우선, `vps-5`와 로컬)
- 대상: T5Gemma 2 270M-270M, **어휘 pruning 사본**(한·영·일·중 사용 토큰, 사본만 생성), LoRA(attention 위주, r=16), 그래디언트 체크포인팅 옵션.
- 측정: 입력 길이 256/512/1024 토큰에서 학습 step 시간, 피크 RAM, 에폭 추정 시간. **VPS 메모리 상한(약 6.5GB)** 이내에서 가능한 최대 길이와 배치를 결정한다.
- 판단: 3,320쌍 + 정상 identity 쌍 × 에폭 수의 총 시간이 호스트당 48시간 이내인가. 초과하면 길이 상한·에폭·데이터 시간을 조정하고 기록한다.
- 로컬에서도 동일 probe를 수행해 로컬 학습 가능성(경합 시 영향 포함)을 보고한다(참고).

### D-6.2 데이터
- 학습: F5 2,000쌍, F6 1,320쌍(AI Hub 71560 유래 오류→정답), **F4 정상 identity 쌍 약 2,000**(D-049의 정상 문장; 아직 없으면 공개 자연 문장에서 만들어 분할 후 사용, 평가 세트와 중복 금지).
- 평가(분리): F5·F6의 holdout, 정상 문장 ≥ 600(과교정 측정), 사람 표본 ≥ 50.
- **P1 소규모 평가(로컬 전용, 학습 금지):** 사용자 메모리 문장 약 30~50건에서 F5 출력을 사람이 점검한다. 메모리 문장은 VPS·외부 API로 보내지 않는다.

### D-6.3 구성
- **A1-all:** F5 + F6 + F4 identity 멀티태스크 LoRA(작업 태그 사용). 먼저 이것 하나를 수행한다.
- timing probe 결과에 따라 **A1-F5**(F5 단독)와 **A1-F6F4**를 다른 VPS에 병렬 배치할 수 있다(간섭 확인용). 호스트가 비는 Wave 2에서 한다.
- A1p(EG2 pooled 프리픽스)는 A1 파일럿이 통과한 뒤에만(C-11.2).

### D-6.4 평가 지표 (판정 아님, 파일럿 판단용)
- 슬롯 보존율(AM-4 정의, 검증기 통과 후), 환각 슬롯, **정상 문장 보존률**(G-C4와 같은 정의), 교정 precision/recall, 사람 표본 적합, 생성 지연(참고).
- 정상 문장 보존률은 n ≥ 600에서 Clopper-Pearson 구간과 함께 보고한다.

### D-6.5 후속
- 파일럿 결과로 CP-D2에서 F5 방향(네이티브 디코더 유지 / 데이터 추가 / 중단), F4·F6의 생성형 경로 가능성을 결정한다.

**산출물:** `reports/D6_a1_timing_probe.md`, `reports/D6_a1_pilot.md`

## D-9. Wave 계획, 호스트 배분, 의존성

### D-9.1 Wave 계획

## D-10. Wave 0 작업 상세

### D0-a. 정규화 불일치 규명 (로컬, 최우선)
- **증상:** Notesoop 공백 무시 CER 17.41%(구 정규화) → 18.96%(통일 정규화)로 **상승**, 공백 포함은 19.10% → 16.93%로 **하락**. 구두점 제거만으로는 설명되지 않는다.
- **조사:**
  1. FLEURS 참조 필드(`raw_transcription` 대 `transcription`)를 구/신 정규화가 각각 어느 쪽으로 썼는지.
  2. 정규화 단계(NFC/NFKC, 소문자, 구두점, 숫자, 영문, 공백)를 하나씩 켜고 끄며 **단계별 CER 표**를 시스템 3종(Notesoop, komixv2, whisper-turbo)에 대해 작성한다(저장된 가설 전사를 재사용, 재디코딩 불필요).
  3. 숫자(아라비아 숫자 대 한글 수사)와 영문 처리가 시스템마다 다르게 영향을 주는지.
- **산출:** 단일 정규화 규칙을 확정해 `eval/normalize.py`에 고정하고(코드 상수 한 곳), 3종 시스템의 dev·test CER을 **재계산**한다(재측정이 아니라 재계산). 결과가 이전 판정(G-C2 FAIL, 순위)에 영향을 주는지 보고한다.
- 이후 모든 CER은 이 정규화를 쓴다. `reports/D0a_normalization.md`

### D0-b. 다운스트림 지표 (로컬)
- 시스템 3종의 전사 `hyp_i`와 정답 `ref_i`(FLEURS test 382, Kspon eval_clean 100)에 대해 EG2 텍스트 Q8(문서용 접두사, `docs/prefix.md`)로 문장 임베딩을 만들고 다음을 보고한다(정보용).
  - 코사인(`hyp_i`, `ref_i`)의 분포(평균, p5).
  - 정답 코퍼스에서 `hyp_i`로 `ref_i`를 찾는 검색 R@1/MRR. 쉬운 코퍼스이므로 **근접 문장 하드 네거티브**(같은 문장 군의 유사 문장)를 포함한 변형도 만든다.
  - CER 구간(0~5, 5~10, 10~20, 20+%)별 코사인 평균(CER과 임베딩 보존의 관계).
- 목적: F2의 요구 정확도(D-4)에 대한 근거. 해석은 사용자가 CP-D1에서 한다. `reports/D0b_downstream.md`

### D0-c. VPS 재기동·점검·카나리 (VPS 5대, 병렬)
- 5대 기동, 호스트별 `df`·RAM·시계·네트워크 대역(로컬 ↔ VPS rsync, HF 다운로드)을 실측한다. venv lock 일치, 모델 파일 SHA256 확인.
- **오디오 Q8 카나리 parity**(미완이면): 로컬에서 만든 Q8 오디오 그래프를 `vps-1`에 배포(SHA256 검증, 이어받기)해 고정 입력 20~50개의 출력 cosine을 로컬과 비교(기대 ≥ 0.999). 이상이 없으면 나머지는 해시·CPU 플래그 동일 확인으로 대체한다.
- 호스트별 **데이터 예산(GB)**과 확정 H를 산정해 보고한다. `reports/D0c_vps_ready.md`

### D0-d. 비용 probe (VPS, 로컬 병행)
- **추출 RTF:** 타워 Q8 특징 추출 RTF를 VPS(1~2대)와 로컬에서 측정(30분 분량 샘플). 추출에 필요한 총 시간을 추정한다.
- **학습 비용:** reader(D-5.5 사양)를 1시간 분량 특징으로 1에폭 학습해 에폭 시간·피크 RAM을 측정, H와 E_max를 사전 선언 범위(48시간/호스트) 내에서 확정한다.
- 결과를 D-5.6 비용 규칙에 따라 사양 조정과 함께 보고한다. `reports/D0d_cost_probe.md`

### D0-e. 그래프 출력·탭 확인 (로컬)
- A2 Q8 다층 그래프의 출력 목록(12층 hidden, `audio_features`, pooled)을 확인해 D-5.4의 특징을 모두 얻을 수 있는지 보고한다.
- 운영 그래프 복사본에서 6/8/10층 탭이 가능한지(중간 텐서 존재 여부)와, A2 그래프와 같은 입력에서 대응 출력의 일치(코사인)를 확인한다. 결과는 D-β가 지지될 때의 **단일 상주 세션** 설계에 쓴다.
- G-A3S 보완(프레임별 최소·하위 분위수)도 이 단계에서 보고한다. `reports/D0e_graph_taps.md`
