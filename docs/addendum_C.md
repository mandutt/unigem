## C-2. 확장성 보존 설계 (EG2 hidden 비채택 시 결합 구조)

> **배경:** 사용자의 우려는 "EG2 hidden을 쓰지 않으면 텍스트 생성 디코더 결합과 향후 확장이 막히지 않는가"이다. 결론: **막히지 않는다.** 이번 결정은 *텍스트 토큰 hidden을 텍스트 생성 과제의 입력으로 쓰는 경로*만 닫는다. 아래 설계로 나머지 결합 경로를 열어 둔다.

### C-2.1 결합 수준 정의 (3단계)

| 수준 | 내용 | 상태 |
|---|---|---|
| **L0 텍스트 인터페이스** | EG2 측 출력(STT 텍스트, 사용자 입력, 검색된 메모리 텍스트)을 **텍스트로** 디코더에 전달. 토크나이저 분절이 두 모델에서 동일(H4′ 4,695/4,695)하므로 재토큰화 손실이 없음 | **기본 구현(지금)** |
| **L1 pooled 벡터 조건화** | EG2 `sentence_embedding`(768d)을 작은 투영(MLP)으로 디코더 프리픽스 토큰 k개로 주입. LoRA 학습과 함께 학습 | **선택 아블레이션**(C-11의 arm A1p), 게이트 없음 |
| **L2 토큰 hidden 어댑터** | EG2 토큰 hidden → 어댑터 → 디코더 cross-attention | **보류**. 재개 조건(C-2.4)을 충족할 때만 |

### C-2.2 잃는 것과 잃지 않는 것 (보고서에 그대로 기록)

- **잃는 것:** (a) 텍스트 생성 때 EG2 텍스트 타워를 인코더로 재사용하는 RAM 절감 — 디코더는 T5Gemma 2 **자체 인코더**를 별도로 로드해야 함. (b) 토큰 수준의 연속 표현 공유.
- **잃지 않는 것:** EG2의 pooled 임베딩(검색, 언어 판정, 이모지 태깅, 라우팅·군집), 오디오·비전 hidden(STT, 태깅), 상주 단일 세션 구조. 디코더가 **온디맨드**이므로 (a)의 비용은 상주 RAM이 아니라 **생성 작업 중의 일시 RAM과 콜드 스타트 지연**이다. 이 비용은 C-11에서 **정량 측정**한다(측정 전에 "작다"고 단정하지 않는다).
- **증거의 범위:** 이번 결과는 *텍스트 토큰 hidden → 텍스트 과제*에만 해당한다. **오디오·비전 hidden → 텍스트 생성**에는 전이되지 않으며, 그 경로는 별도 게이트와 사전 선언 실험으로만 평가한다.

### C-2.3 보존 자산 (삭제·덮어쓰기 금지)
- `onnx/`의 텍스트·오디오 연구용 그래프와 운영용 Q8 그래프(다층 출력 포함)
- 코퍼스 v2, P1 데이터와 라벨, 프로브·헤드 학습 코드, 학습된 헤드 체크포인트
- H4′ 분절 정렬 결과와 **문자열 기반 토큰 id 변환표**(EG2 ↔ T5Gemma 2)
- 모든 보고서의 원시 결과(JSONL). `assets/eg2_text_hidden/README.md`에 위 자산의 목록과 재현 방법을 기록한다.

### C-2.4 L2 재개 조건 (사전 선언, AM-8)
다음 중 하나를 충족하고 **새로 사전 선언한 실험**을 통과한 경우에만 L2를 재개한다. 이전 FAIL을 재판정하는 것이 아니다.
1. **실제 오류 데이터**가 확보되어 저데이터 영역(학습 ≤ 10%에서 EG2 이득 +7.5%p, P1 결과)이 실제 운영 조건임이 확인되고, 문장 단위 주지표를 새로 선언한 P2 파일럿에서 기준을 넘을 때.
2. **오디오·비전 → 텍스트 생성** 같은 새 요구가 생겨 연속 표현 입력이 필요해질 때(해당 모달리티의 hidden으로 별도 게이트 설정).
3. C3 arm A1이 한국어 메모리 요약에서 실용 품질에 도달하지 못해 대안이 필요해질 때.

### C-2.5 AM-8: 비채택 결정의 표기와 재개 규칙
- 폐기 결과는 "**제품 경로 비채택**"으로 표기한다. 이는 사전 등록된 결과(B-12 1행)를 바꾸지 않는다(임계값·판정 불변).
- 재개는 반드시 **새 사전 선언 실험**을 거치며, 이전 실험의 사후 재해석으로 하지 않는다(AM-5(iii) 유지).

### C-2.6 디코더 인터페이스 명세 (L0)
- 입력: UTF-8 텍스트 + 작업 태그(`F4`, `F5`, `F6`) + 제약(최대 길이, 슬롯 검증 활성 여부).
- 출력: 생성 텍스트 + 신뢰도 지표 + 슬롯 검증 결과 + `accepted/rejected`.
- 수명주기: 온디맨드 로드 / 유휴 타임아웃 언로드 / 로드 실패 시 폴백(원문 저장, 규칙 결과, 기존 ASR 경로).
- 토크나이저: 디코더 측 토크나이저로 재토큰화(분절 동일성은 H4′로 확인됨, 변환표는 보존 자산).
- **연속 입력 슬롯**(L1/L2용 프리픽스 입력)은 인터페이스에 **예약만** 하고 구현하지 않는다.

- 이미 수행했다면 결과를 보고서에 포함하고 이 항목은 종결한다. **판정은 하지 않는다**(탐색적).
- 우선순위: 낮음(다른 항목을 막지 않는 한 수행).

## C-6. F4-v2: 규칙 + LM 점수 + 보수적 수락 (재설계 파일럿)

**문제:** 토큰 단위 탐지 헤드는 최고 성능이어도 정상 문장 오탐률이 37%여서 G-C4(정상 보존 ≥ 99.5%, 과교정 ≤ 0.5%, 정상 문장 ≥ 600)를 만족시키기 어렵다. 특징 선택(EG2 여부)보다 **과제 설정**이 병목이다.

### C-6.1 구성
1. **규칙 후보 생성:** 혼동쌍(되/돼, 안/않, 로서/로써, 던/든, 낫/낳/났 등), 자모 오타 교정, 띄어쓰기 규칙, 사전 기반 후보. 후보는 **원문과의 편집이 작은 것**만 허용.
2. **LM 점수기(2종 비교):**
   - (a) n-gram LM(KenLM 가능 시, 공개 한국어 텍스트로 학습, P0)
   - (b) T5Gemma 2 디코더 우도 점수(C-11의 환경 재사용; 점수 방식은 사전 선언 문서에 기록)
3. **보수적 수락 규칙:** 후보의 점수 이득이 마진 이상일 때만 적용, 아니면 원문 유지(reject). 마진은 **검증 분할에서만** 정한다.
4. **슬롯 가드:** 식별자·숫자·경로 등 보존 슬롯(AM-4)이 바뀌는 후보는 자동 기각.

### C-6.2 평가
- 데이터: P1 합성 테스트(정상 문장 ≥ 600 포함)와 AI Hub 교정 쌍(C-5의 외부 평가). 학습·마진 선택은 검증 분할만 사용.
- 지표(G-C4 정의 그대로, AM-4): **정상 문장 보존률**, **과교정률**, 교정 precision/recall, **coverage–precision 곡선**, 의미 변화가 있는 변경의 사람 표본 점검(≥ 50건).
- 판정: G-C4 임계값을 그대로 사용한다(Clopper-Pearson, 정상 문장 n ≥ 600). 통과하지 못하면 해당 점수기 구성은 FAIL.
- 비교: 규칙만, 규칙 + n-gram, 규칙 + 디코더 점수.
- **사전 선언:** 점수기·마진 선택 방식·수락 규칙을 평가 데이터를 보기 전에 `gates.md`에 기록하고 해시를 남긴다.

### C-6.3 일정과 의존성
- 규칙·n-gram 구성은 디코더 없이 바로 시작할 수 있다. 디코더 점수(b)는 C-11 환경이 준비된 뒤에 추가한다.
- 호스트: `vps-4`(규칙·n-gram), 디코더 점수는 `vps-1`.

## C-7. L1: 출력 탭 추가형 개조 가능성 확인 (시간 제한)

1. **중단 사항:** G-A3L-R 98.18%를 올리려는 분석·재측정은 하지 않는다. FAIL 유지, 운영 LID 그래프 유지.
2. **확인할 것 (1회 작업 단위로 시간 제한, 초과하면 현 상태를 보고하고 중단):**
   - 운영 LID 그래프 파일이 최적화·융합을 거쳐 저장되었는지(중간 텐서가 남아 있는지).
   - 남아 있으면 **복사본**에 중간 텐서를 추가 출력으로 노출하고, 원 그래프와 pooled 출력이 **동일**(최대 절대 오차 ≤ 1e-6, 220클립 argmax 일치율 100%)한지 확인.
   - 사라졌으면 운영 양자화 절차를 코드로 재현할 수 있는지(레시피의 존재 여부)만 확인하고, 재현이 어렵다면 그 사실을 보고한다.
3. **판정:** 탭 추가 그래프(원 그래프와 동일 출력)가 확보되면, 같은 G-A3L-R 규칙을 이 후보에 적용해 PASS/FAIL을 기록한다. 동일 출력이면 사실상 PASS이나 **기록을 남긴다**.
4. **불가능한 경우:** 두 그래프 병존(운영 LID + 신규 다중 출력)의 **오디오 타워 Q8 이중 상주 RAM**을 추정해 보고하고, 상주 정책 결정(사용자)에 맡긴다.
5. 같은 220클립을 다시 사용한 재판정은 금지(B-7 규칙 유지).

**산출물:** `reports/C7_l1_tap_feasibility.md` — 호스트: 로컬(운영 자산 읽기 전용)

## C-8. C2-A1: Notesoop CER·RTF 기준선 (최우선)

**이유:** F2가 프로젝트의 주축이 되었고, 이 결과가 F2의 채택·미세조정·자체 학습 방향과 오디오 단일 세션 구조의 타당성을 결정한다.

1. **평가 세트:** Zeroth-Korean의 **test 분할만**, FLEURS ko test(전체). 9.6GB 전체 다운로드 금지. 디스크 여유 2GB 가드.
2. **비교 대상:** komixv2, whisper-turbo(한국어 강제), Notesoop(greedy, 가능하면 +KenLM).
3. **정규화:** 구두점 제거, 대소문자 통일, **공백 무시 CER을 주지표**로, 공백 포함 CER과 WER를 병기. 모든 시스템에 동일한 정규화 코드를 적용한다.
4. **통계:** 문장 단위 부트스트랩 95% 구간, 시스템 간 쌍 비교(대응 부트스트랩 차이).
5. **환경:** CER은 VPS 가능, **RTF·RAM은 로컬 CPU(스레드 6)**에서 판정용으로 측정. VPS 값은 참고. 청크(16초 + 겹침 1초) 처리 방식과 병합 오류(경계 중복·누락)도 길이가 긴 샘플로 점검한다.
6. **적용 게이트:** G-C2(FLEURS ko test greedy CER ≤ 15%). Notesoop 보고치(Zeroth 16.21%)가 기준보다 높으므로 통과를 가정하지 말고 실측한다.
7. **추가 보고:**
   - Notesoop의 입력 특징 지점(오디오 타워 → 정규화 → 투영 256d → L2)과 우리 ONNX 출력의 대응 관계.
   - G-A3S/G-C2a는 승인 대기 제안 게이트이므로 **측정만** 하고 판정으로 쓰지 않는다. 승인 요청은 결과와 함께 올린다.
   - KenLM 설치 가능성(Linux 확인됨, Windows 로컬 확인 필요).
8. **결정 지점(CP-C1):** 채택 / 채택 + 미세조정 / 자체 학습 / 폐기. 보고서는 선택지별 비용과 예상 이득을 비교표로 제시한다.

**산출물:** `docs/STT/reports/C8_c2a1_cer.md` — 호스트: `vps-3`(CER), 로컬(RTF·RAM)

## C-9. C1 파일럿 (PyTorch, B-10.2와 동일)

- 텍스트+비전(440M)을 PyTorch FP32로 실행해 이모지 검색 정확도를 G-C1 기준(top-1 ≥ 70%, top-3 ≥ 85%, margin 통과 후 부적절 태그 ≤ 5%, 이미지 ≥ 100장, Wilson 95%)으로 판정한다.
- 이미지는 P0 공개 데이터. 라벨링 프로토콜은 plan v0.5 C1(후보 풀 혼합·출처 숨김, VLM은 후보 생성원). 사용자 라벨링용 시트를 생성하고 라벨링 완료를 기다린다.

## C-10. G-DATA 단계 승인 구조

**배경:** F5(T5Gemma 2 270M이 한국어 메모리 요약을 실용 품질로 하는가)가 가장 큰 미지수이고, 제안서는 최대 30,000건/약 $150이다. 위험을 줄이려 단계로 나눈다.

1. Hermes는 `reports/G-DATA_proposal.md`를 **2단계 구조로 개정**해 사용자에게 승인을 요청한다. **승인 전 API 호출 금지.**
   - **1단계(파일럿):** 약 3,000 쌍, 비용 상한을 명시(제안서의 단가 기준 비례 계산). 목적은 LoRA 학습 가능성과 슬롯 보존·품질의 초기 확인.
   - **2단계(확장):** 나머지 규모. **1단계 통과 시에만** 승인을 요청.
2. **1단계 통과 판단(제안, 게이트 아님, 승인 시 확정):** 슬롯 보존율(AM-4 기준, 검증기 통과 후 채택분) ≥ 90%, 신규 슬롯 생성(환각) ≤ 3%, 사람 표본(≥ 50건) 적합 ≥ 60%. 이 값은 2단계 진행을 위한 **탐색적 기준**이며 G-C5 판정과 별개다.
3. **데이터 규칙:** API 입력은 **P0(공개·합성)만**. 합성 입력에 개인정보가 없음을 확인하는 절차 포함. 학습·검증·평가 분할 전에 중복 제거, **평가 세트와의 누수 검사**(문장·근접 일치). 평가용 세트는 공개 데이터 또는 규칙 합성으로 분리해 두고, P1은 로컬 평가에만 쓴다.
4. 생성 모델, 날짜, 프롬프트 템플릿 해시, 호출 수, 실제 비용을 기록한다.

**산출물:** 개정된 `reports/G-DATA_proposal.md`(승인 요청) — 호스트: `vps-1`

## C-11. C3 arm A1 파일럿 + 확장성 비용 정량화 (G-DATA 1단계 승인 후)

### C-11.1 arm A1 (네이티브 T5Gemma 2 인코더 + 디코더, LoRA)
- 학습: LoRA(attention 위주), 원본 가중치 불변. 어휘 pruning **사본**(한·영·일·중 사용 토큰만)으로 크기·RAM을 줄이고 품질 변화를 측정한다.
- 과제: F5(요약), F6(STT 후처리 교정)의 소규모 파일럿.
- 평가: 슬롯 보존율(AM-4), 환각 슬롯, 사람 표본, 지연(입력 ≤256 토큰, 출력 ≤128 토큰, p50/p95, 로컬). **지연 소프트 목표(p50 약 5초, p95 약 10초)는 판정 기준이 아니라 보고 항목.**
- ONNX Q8 export, KV cache 분리, 동적 INT8 품질 점검(T5 계열 FFN 출력 FP32 유지 옵션)은 plan v0.5 C3 사양을 따른다.

### C-11.2 arm A1p (선택 아블레이션, L1)
- A1에 **EG2 pooled 벡터 프리픽스**(768 → k×hidden 투영, k ∈ {1, 4})를 추가해 LoRA와 함께 학습한다.
- 목적: pooled 임베딩이 디코더 조건화에 쓸모 있는지를 **최소 비용으로** 확인(L1 근거 확보). 게이트 없음. A1 파일럿이 통과한 뒤에만 수행.

### C-11.3 확장성 비용 정량화 (C-2.2의 후속, 필수)
- T5Gemma 2 인코더+디코더의 **FP32 / Q8 / (어휘 pruning 사본)별 파일 크기, 로드 시간(콜드), 유휴 RSS, 피크 RSS**를 로컬에서 측정한다. VPS 값은 참고.
- "EG2 텍스트 타워를 인코더로 재사용했다면 절약되었을 용량"을 **EG2 텍스트 타워 Q8 크기와 T5Gemma 2 인코더 크기의 차이로 추정**해 병기한다(추정임을 표기).
- 온디맨드 정책(유휴 타임아웃 후보값)과 폴백 동작을 함께 보고한다.
- **산출물:** `reports/C11_decoder_cost.md`, 구성 매트릭스(A7_config_matrix) 갱신 — 호스트: `vps-1`(학습·참고), 로컬(판정 측정)

## C-13. 평가 하네스 품질 규칙 (AM-7)

모든 평가·학습 코드에 다음 자동 점검을 **의무화**한다.

1. **하한 점검:** AUPRC·정확도 등 지표가 0.0 또는 무작위 기준(양성 비율)과 같거나 낮으면 경고하고 결과 저장 전에 중단한다(AUPRC 0.0 사건 재발 방지).
2. **dtype·마스크·인덱스 정합 단위 테스트:** 라벨 dtype, 마스크 dtype, 토큰-문자 span 정렬, 분할 누수를 검증하는 테스트를 `eval/tests/`에 둔다.
3. **결함 수정 전후 provenance:** 결함 수정 이전에 산출된 결과에는 `pre-fix` 표시를 하고 최종 판정에 쓰지 않는다. 수정은 커밋 후 재실행하며 커밋 해시를 보고서에 기록한다.
4. **seen/unseen 등 분석 정의는 코드 상수 한 곳에서 정의**해 층·모델마다 달라지지 않도록 한다.
5. **대용량 로딩:** 거대한 `.npz`를 한 번에 읽지 않는다(샤딩, 메모리 매핑, 필요한 층만 로딩).
