## A-2. AM-1: G-A3L 개정 (G-A3L-R)

### A-2.1 배경
- 사전등록 G-A3L: 기존 판정기에 새 ONNX 출력을 넣어 argmax 일치율 ≥ 99%, 확신 오판 증가 0.
- 현 결과: 44클립에서 FP32 43/44(97.7%) → FAIL(등록 기준), Q8 44/44. D-011은 "FAIL 유지 + 1건 예외 승인"으로 기록되어 있다.

### A-2.2 개정 내용 (임계값 불변, 대상·표본·보조 판정 명확화)

| 항목 | v0.5 (기존) | G-A3L-R (개정) |
|---|---|---|
| 판정 대상 | "새 ONNX"(모호) | **교체 후보인 Q8 운영 경로**(텍스트·오디오 q8 그래프로 만든 pooled 출력). FP32 연구용 그래프는 **참고 보고만**, 판정 대상 아님 |
| 평가 세트 | 44클립 | **기존 운영 평가 세트 전체**(보고서 기준 220클립. 실제 규모를 Hermes가 확인해 보고하고, 220이 아니면 사용자에게 알린다) |
| 필수 조건 1 | 일치율 ≥ 99% | **그대로 유지**: argmax 일치율 ≥ 99% |
| 필수 조건 2 | 확신 오판 증가 0 | **그대로 유지**: 기존 판정기의 운영 확신 기준(보고서상 margin ≥ 0.05, Hermes가 코드로 확인) 하에서 정답 라벨 기준 오판 건수가 기존 대비 증가 0 |
| 불일치 분석 | 없음 | **의무**: 불일치 건마다 정답 라벨, 기존/신규 argmax, 양쪽 margin을 표로 기록 |

### A-2.3 판정 규칙 (사전 선언)

- **PASS:** 필수 조건 1·2 모두 충족.
- **PASS-R(구제 통과):** 일치율 < 99%이지만 아래를 **모두** 충족.
  1. "신규만 틀림"(정답 기준 기존 정답, 신규 오답) 건수 = 0
  2. 확신 오판 증가 = 0
  3. 모든 불일치가 사용자 보고서에 건별로 제시됨
  
  PASS-R은 **사용자 확인 후** CP에서 PASS로 인정한다. Hermes가 임의로 PASS로 처리하지 않는다.
- **FAIL:** 위 둘 중 어느 것도 충족하지 못함. 이 경우 Q8 운영 그래프 교체는 보류한다.

### A-2.4 보고 항목 (필수)
- 220클립(또는 확인된 전체)에 대해 기존 대 신규(Q8)와 기존 대 신규(FP32)를 각각 보고한다.
- 일치율과 **Clopper-Pearson 95% 신뢰구간**.
- 정답 라벨 기준 정확도(기존/신규)와 대응 비교: 불일치 쌍의 방향별 건수(신규만 정답 / 기존만 정답 / 둘 다 오답), 정확 McNemar 검정 p값.
- margin 분포(기존 대 신규)와 확신 판정 비율(abstain 비율 변화).
- 유사 언어쌍(id/ms 등) 혼동 행렬.
- 44클립 결과(D-011)와의 관계: 220클립에는 44클립이 포함될 수 있으므로 겹치는 부분을 표시한다.

### A-2.5 기록 정정
- `gates.md`: G-A3L의 이전 결과를 **"FAIL(FP32, 44클립, 등록 기준)"**으로 정정하고, "예외 승인"이라는 표현을 제거한다.
- `decisions.md`: D-011을 철회하는 신규 결정을 추가한다(사유: 판정 대상 명확화와 표본 확대, 철회가 아니라 후속 개정임을 기록).
- 220클립 측정 결과는 **G-A3L-R 판정**으로 기록하고, 44클립 FP32 FAIL은 이력으로 남긴다.

### A-2.6 수행 지침
- 로컬 CPU에서 수행한다(몇 분 규모 예상). 기존 평가 세트와 판정기는 **읽기 전용**.
- **측정 전에** `decisions.md`에 이 개정(AM-1)과 판정 규칙을 기록하고 해시를 남긴다. 기록 시각이 측정 시작 시각보다 빨라야 한다.

### A-3.2 B1.5-0: 층 정의 확인 (최우선, 수 분 규모)
1. ONNX 출력 `tok_h_l00/l04/l08/l12/l16/l20/last`가 HF `hidden_states`의 어느 인덱스인지 매핑표를 만든다(예: `hidden_states[0]` = 임베딩 출력, `[k]` = k번째 블록 출력).
2. PyTorch 원본으로 `embed_tokens(input_ids)`와 (모델이 적용한다면) 임베딩 스케일링을 직접 계산해 `tok_h_l00`과 비교한다: cosine, 최대 절대 오차. 일치하지 않으면 l00이 첫 블록 출력일 가능성을 검증한다(`hidden_states[1]`과 비교).
3. 같은 토큰이 서로 다른 문맥에 있을 때 l00 값의 변동을 (a) ONNX 출력 (b) PyTorch `hidden_states[0]` (c) `hidden_states[1]`에서 각각 측정한다. 순수 임베딩이면 변동이 0이어야 하므로, 0.869는 왜 나왔는지(패딩, 위치, 어텐션 마스크 영향 포함) 원인을 보고한다.
4. 입력 형식 점검: BOS/EOS 처리, 패딩 위치, 마스크, **EG2 텍스트 태스크 접두사**(모델 카드의 문서용/질의용 접두사 문자열을 확인해 기록). B1이 어떤 형식으로 실행됐는지 소급 확인한다.
5. **산출물:** `reports/B1_5_0_layer_definition.md` (매핑표, cosine, 원인 분석, 입력 형식).

> 판정: l00이 순수 임베딩이면 G-B1의 l00 통과는 "토크나이저가 결정적"이라는 것만 보여준 것이고, G-B1의 의도(EG2 hidden의 표면 정보 보존)는 미검증이다. `gates.md`의 G-B1을 **"l00 형식 충족, 의도 미확인 → G-B1.5로 이관"**으로 표기하고 "조건부 PASS"라는 표현은 쓰지 않는다.

### A-3.4 B1.5-1: 프로브 v2 (임베딩 테이블 공유 방식)

**모델.** 층 특징 `h`(512차원)에 대해 `z = W·norm(h) + b`(512→512 선형), 로짓 = `z · Eᵀ`. `E`는 EG2 입력 임베딩 테이블(동결, 전체 어휘). 클래스별 파라미터가 없어서 학습에 없던 토큰도 예측할 수 있다.

**학습.**
- 훈련 시 소프트맥스 후보는 샘플링한다: 배치 내 정답 토큰 ∪ 코퍼스 등장 토큰 집합 ∪ 무작위 음성 약 2만 개. 전체 어휘(262K) 소프트맥스를 매 스텝 계산하지 않는다.
- **평가는 전체 어휘 대상 argmax**(청크로 나눠 계산)로 한다.
- 정규화: 층별로 **특징 표준화**(학습 분할에서 평균·분산 추정) 또는 파라미터 없는 RMSNorm을 쓴다. 두 방식을 모두 보고한다(층별 스케일 차이와 중간층의 큰 활성값 때문).
- 최적화: AdamW, **학습률 {1e-4, 3e-4, 1e-3, 3e-3} 탐색**, 가중치 감쇠 소탐색, 최대 100 epoch, 검증 정확도가 10 epoch 개선되지 않으면 조기 종료. **층마다 같은 탐색 예산**을 쓴다.
- 시드 3회, 중앙값과 범위 보고.

**대상 층:** 임베딩 출력(`hidden_states[0]`), l00, l04, l08, l12, l16, l20, last, 그리고 (선택) 상위 2~3개 조합 연결.

**지표 (테스트 분할, 모두 95% 신뢰구간):**
- 토큰 top-1 정확도: 전체, 숫자, 언어별(ko/en/ja/zh), **학습에 등장한 토큰 종류 / 등장하지 않은 종류를 분리**
- **식별자·숫자 span exact match**(문자 오프셋 기준): 실제 식별자 set과 틀 단위 분리 테스트로
- span 복원 **문자 단위 편집거리**(평균·분포)
- **학습 정확도 병기**: 층별 과소적합(최적화 문제)과 정보 손실을 분리하기 위함
- 신뢰구간: 비율은 Wilson 95%, 편차는 문장 단위 부트스트랩(1,000회)

**비단조 점검:** B1에서 관찰된 l08 이상치가 재현되는지 별도로 보고한다. 재현되지 않으면 B1의 층 비교를 무효로 기록한다.

**산출물:** `reports/B1_5_1_probe_v2.md`, 층별 결과 JSONL.

### A-3.5 B1.5-3: 문맥 가치 테스트 (F4 핵심)

**목적:** 깊은 층이 **l00으로는 얻을 수 없는 문맥 정보**를 주는지 본다. 차이가 없으면 EG2 hidden은 F4에 가치가 없다.

**과제 (모두 층별 선형 헤드, 필요 시 소형 MLP를 보조 비교):**

| ID | 과제 | 라벨 | 최소 표본 |
|---|---|---|---|
| T1 | 오타 토큰 탐지 | noisy 문장의 토큰별 "오류 span에 속함" 여부(clean 대비 정렬) | 테스트 토큰 수천 개 이상, 오류 span ≥ 600 |
| T2 | 한국어 띄어쓰기 오류 탐지 | 토큰 경계에서 "공백이 있어야/없어야 함" | 테스트 경계 ≥ 3,000 |
| T3 | 최소쌍 구분: 되/돼, 안/않 | 문맥에 맞는 형태(원문 문장은 공개 코퍼스에서 맞는 용례만 선택, 틀린 쪽은 규칙으로 생성) | 유형당 ≥ 500쌍, 테스트 ≥ 150쌍 |

**기준선 (필수):**
- **BL-0:** l00 단일 토큰
- **BL-1:** l00 **주변창 연결**(대상 토큰 ±2토큰의 l00 이어 붙임). 문맥을 명시적으로 주는 기준선이므로, 깊은 층이 이것을 못 넘으면 EG2의 문맥화는 가치가 없다.

**지표:** T1/T2는 토큰 단위 F1과 AUPRC, 문장 단위로 "오류 존재" 탐지 정밀도(재현율 고정), T3는 정확도. 모두 문장 단위 클러스터 부트스트랩 95% 신뢰구간.

**사전 선언 판정(§A-3.8의 G-B1.5-b):** 어떤 층 L*이 BL-1 대비 +3%p 이상이고 부트스트랩 하한이 0을 넘는 과제가 T1~T3 중 **2개 이상**이면 "문맥 가치 있음".

### A-3.6 B1.5-4: 복사 충실도 프록시 (F5 핵심, 우선순위 2)
B1.5-1·3의 결과가 나온 뒤, 문맥 가치가 확인된 층 후보에 대해서만 수행한다.

## A-4. AM-2: 식별자 지표 span 정의의 정식 개정 기록

**기록 내용 (`decisions.md`와 `gates.md`):**

## A-5. AM-3: 모든 게이트의 최소 표본 수와 신뢰구간 규칙

**일반 규칙(신규):** 모든 게이트는 판정 전에 **최소 평가 표본 수**와 **신뢰구간 방법**을 선언한다. 점추정만으로 PASS/FAIL을 내리지 않는다. 0건 오류 검증에는 **rule of three**(오류율 95% 상한 ≈ 3/n)를 쓴다.

**기존 게이트에 대한 적용 (임계값 불변):**

| 게이트 | 최소 표본(제안) | 신뢰구간 | 비고 |
|---|---|---|---|
| G-A3L-R | 220클립(전체) | Clopper-Pearson | §A-2 |
| G-A3 / G-A4 | 층별 cosine은 입력 ≥ 200개(길이 구간별) | 최소·분위수 보고 | 최소값이 기준 |
| G-B1 → G-B1.5 | §A-3 | Wilson / 부트스트랩 | |
| G-C1 | 이미지 ≥ 100장(권장 150장) | Wilson 95% | top-1 ≥ 70%는 n=100에서 ±9%p 정도의 불확실성이 있으므로 하한도 함께 보고 |
| G-C2 | 평가 발화 ≥ 300문장(FLEURS ko test 전체 사용 권장) | 부트스트랩(문장 단위) | CER 기준 |
| G-C4 | **정상 문장 ≥ 600** | Clopper-Pearson | 보존률 ≥ 99.5% 입증에 최소한 필요 |
| G-C5 | **슬롯 ≥ 300**(0.5%까지 보려면 ≥ 600) | Clopper-Pearson | 슬롯 보존율 ≥ 99% |

표본이 부족하면 해당 게이트는 PASS가 아니라 **INCONCLUSIVE**로 기록하고 표본 확대를 요청한다.

## A-6. AM-4: F4/F5 지표의 정의 (측정 전 고정)

### A-6.1 슬롯 정규화 (F5, G-C5)

슬롯은 **엄격(strict)**과 **정규화(canonical)** 두 모드로 모두 보고한다. 게이트 판정은 아래를 따른다.

| 범주 | 비교 방식(판정) | 정규화 규칙 |
|---|---|---|
| 식별자, 해시, 모델명, 파일명 | **strict**(문자열 일치) | 없음 |
| 경로 | **strict**(구분자·대소문자 보존) | 없음 |
| URL | canonical | 스킴·호스트 대소문자, 끝의 `/` 무시 |
| 버전 | canonical | `v` 접두사 유무 무시, 의미 있는 자리 보존 |
| 숫자 | canonical | 천 단위 구분 제거, 전각→반각, 값이 같으면 동일(`3만5천`은 값으로 해석 가능하면 동일, 해석 불가면 strict) |
| 단위 | canonical | 대소문자·공백 무시, **GB와 GiB는 다른 단위** |
| 날짜·시간 | canonical | ISO 형태로 변환 후 비교(`2026-11-02` = `2026년 11월 2일`), 상대 표현("내일")은 제외 |

- **신규 슬롯(환각):** 출력 슬롯 중 원문의 어떤 슬롯과도 (해당 모드 기준) 일치하지 않는 것.
- 정규화 규칙은 코드로 구현해 `eval/slot_norm.py`에 두고, 단위 테스트(변형 사례 ≥ 50개, 적대적 사례 포함)를 통과해야 측정에 사용한다.

### A-6.2 맞춤법 지표 (F4, G-C4)

- **정상 문장 보존률** = 오류 없는 문장 중 출력이 입력과 **동일**한 비율(공백 정규화 규칙은 보고서에 고정).
- **과교정률** = 오류가 있는 문장에서 **오류 span 밖의 문자가 변경된 문장**의 비율.
- 보조 보고: 교정 precision/recall(편집 단위), 의미 변화가 있는 변경의 사람 표본 점검(≥ 50건).
- 정의안은 사용자 승인 대상이다. 전달된 이 문서를 승인으로 본다. 이견이 있으면 Hermes에게 알린다.

### A-6.3 reject 계열 지표
- 모든 F4/F5 헤드는 **추정 확신도에 따른 적용 비율(coverage)과 정밀도 곡선**을 보고한다(한 점이 아니라 곡선).

## A-7. 오디오 그래프 정책 · 측정 작업

### A-7.1 오디오 그래프 정리 (F-7 대응)
- **주력 연구용 그래프:** `t1600`(16초). Notesoop의 16초 + 1초 겹침 청크와 같은 단위다. (C2-A0 분석에서 청크 규격이 다르면 그에 맞춘다.)
- **보조:** `t500`(짧은 크롭). `t3000`은 폐기 후보다. **폐기 전 사용자에게 보고하고 삭제하지 않는다.**
- **30초 초과 처리 정책(제안):** 16초 청크 + 1초 겹침, 겹침 구간은 중간 프레임에서 병합. 청크는 배치 축으로 처리한다. EG2 오디오 입력 상한(30초)을 넘지 않는다.
- **경계 효과 점검(필수):** 정확한 길이 입력(동적 PyTorch 경로)과 zero-pad + mask 정적 그래프의 **유효 프레임 출력 cosine을 경계로부터의 거리별로** 보고한다(경계 근처 프레임이 열화되는지).
- **특징 출처 일치:** 이후 reader 학습·평가에 쓰는 특징은 **배포에 쓸 그래프와 같은 계열**에서 뽑는다. 연구용 FP32 특징으로 학습한 reader를 q8 특징에 적용한 결과를 G-C2a로 측정한다.

### A-7.2 오디오 q8 지연 측정 (F-11, 즉시 수행, 로컬)
- 대상: `eg2_audio_q8_layers.onnx`(동적, 12층).
- 입력 길이: 5초 / 16초 / 30초 오디오(공개 샘플), 스레드 6.
- 보고: p50/p95 지연, **RTF**(= 처리 시간/오디오 길이), peak RSS, 로드 시간. VPS 값은 참고로만 병기한다.
- 이 결과는 C2-A의 RTF 비교(Notesoop은 Apple Silicon GPU 기준 RTF 0.025~0.035로 보고)의 기준이 된다.

### A-7.3 텍스트 임베딩 테이블 양자화 실험 (F-10, 로컬 + 참고 VPS)
- 가설: 텍스트 Q8(684MB)의 잔여 용량 대부분은 FP32 임베딩 테이블(추정 약 537MB)이다. **먼저 `onnx` 그래프에서 텐서별 크기를 집계해 가설을 확인한다**(추정이 틀렸다면 중단하고 보고).
- 시도: (a) 테이블을 FP16으로 저장하고 Cast, (b) INT8 행 단위 양자화 + 그래프 내 Dequantize.
- 검증: pooled cosine ≥ 0.999, 토큰 hidden 층별 cosine ≥ 0.998(제안), LID 회귀 영향 없음(§A-2의 220클립 재실행), 파일 크기, 로드 시간, RSS.
- 결과는 **새 파일로** 저장하고 기존 운영·현재 Q8 산출물은 건드리지 않는다.

### A-7.4 구성 매트릭스 측정 (G-D 보고용)

판정 기준은 없다. 아래 구성별로 **로컬**에서 측정하고, 구성이 늘어날 때마다 갱신한다.

| 구성 | 유휴 RSS | 피크 RSS | 로드 시간 | p50/p95 지연 |
|---|---|---|---|---|
| 텍스트 Q8 | 기록 | 기록 | 기록 | 512토큰 기준 |
| + 오디오 Q8(같은 프로세스) | | | | 16초 청크 |
| + Notesoop reader (+KenLM) | | | | C2-A4 후 |

- 스레드 6 고정. **두 조건**에서 측정한다: (1) 유휴 시스템, (2) **경합 조건**(Hermes/JEV 등 평소 상주 프로세스가 동작 중. 불가능하면 대체 부하를 재현하고 그 구성을 기록).

## A-8. Phase C 착수 순서와 VPS 배분

### A-8.1 즉시 병렬 착수 (CP2 무관)
1. **C-D0 공개 데이터 조사** (다른 단계의 선행). 코퍼스 v2의 데이터 후보도 함께 조사한다.
2. **C2-A0/A1 Notesoop 코드·라이선스 점검과 독립 평가**(F2 방향 결정). 라이선스는 `LICENSE`뿐 아니라 AI Hub 약관의 파생 모델 영향도 확인한다.
3. **C0 토크나이저 비교, 디코더 분리 타당성.**
4. **비전 타워 ONNX export 착수**(`vps-5`). 오디오 export와 같은 문제(sliding-window `unfold`, 5D 마스크, `Pad` 상수, optimizer가 Clip 상수 삭제)가 발생할 수 있으므로, 이미 확립한 `dynamo + 정적 shape + optimize=False` 조합을 우선 시도한다. 이미지 토큰 예산(기본 280)과 입력 크기는 설정 파일에서 확인해 정적 shape를 정한다. 실패·타임아웃은 1회 기록 후 보고한다(plan §0-5).

### A-8.2 배분 (초안, 한 호스트에 무거운 job은 1개)

| 호스트 | 작업 | 비고 |

## A-9. VPS 관련 후속 작업

### A-9.1 카나리 정합 검증 (F-8)
- **대상:** `eg2-1`(카나리). Q8 텍스트·Q8 오디오 그래프를 배포한다(어차피 EG2 job에 필요한 파일이므로 추가 전송이 아니다). 전송은 SHA256 검증과 이어받기를 지원하는 방식(rsync 등)으로 한다.
- **검증:** 고정 입력 20~50개(텍스트 길이별 + 오디오 5/16초)로 로컬과 pooled·층별 출력 cosine을 비교한다. 기대: ≥ 0.999(Q8 커널 경로 차이 포함). 미만이면 원인(ISA 분기 등)을 보고하고 나머지 호스트로 확대한다.
- **나머지 호스트:** 모델 파일 SHA256, CPU 플래그(`avx2`, `avx512*`, `avx512_vnni`) 동일 여부, 같은 lock 확인으로 대체한다. 어긋나면 확대 검증한다.
- **로컬과의 차이 기록:** 로컬(Ryzen 7600)과 VPS(EPYC)의 명령어 세트 차이가 결과에 영향을 주는지 보고서에 기록한다.

### A-9.2 약관 확인 (F-12, Phase C 본격 착수 전)
- InstaBox 약관에서 장시간 CPU 사용, 트래픽 한도, **계정·인스턴스 구성 조건**(복수 계정 사용 등)을 확인해 사용자에게 보고한다.
- 판정이 불명확하면 사용자에게 질문한다. 약관 위반 소지가 있다고 판단되면 VPS 사용을 **보류하고 보고**한다.
- 결과 회수 규칙을 재확인한다(작업 종료 시 체크포인트·지표·로그를 로컬로 회수한 후 호스트 정리).
