# C-11.3 — 디코더 온디맨드 비용 정량화

- 작성: 2026-11-02
- 대상: Addendum C §C-11.3 (C-2.2 후속, 필수)
- 호스트: 로컬 CPU(6 threads) — 판정용
- 모델: `data/models/t5gemma-2-270m-270m` (T5Gemma2ForConditionalGeneration, 786M params)

## 1. 실측 (FP32, 전체 모델)

| 항목 | 값 |
|---|---|
| 파일 크기 | **1,605.6MB** (safetensors 1,572.2MB) |
| 파라미터 | **786.0M** |
| 콜드 로드 | **9.37s** |
| 유휴 RSS | **3,732.6MB** |
| 피크 RSS (생성 포함) | **3,741.8MB** |
| 생성 | 입력 256토큰 → 출력 129토큰, **16.9s (p50)** |
| 스레드 | 6 |

- 소프트 목표(p50 5s) 대비 **약 3.4배** — 판정 기준은 아니며 보고 항목이다.
- RSS가 파일 크기의 2.3배인 이유: FP32 가중치 + KV cache + activations + vision tower.

## 2. 구성별 크기

| 구성 | 파라미터 | FP32 | Q8(추정/실측) |
|---|---|---|---|
| 전체(비전 포함) | 786.0M | 1,606MB | 동적 INT8 **1,478MB**(−6%) |
| **텍스트 전용**(비전 제외) | **369.2M** | **1,477MB** | **≈369MB** |
| 텍스트 + 어휘 pruning(64k) | 242.4M | 970MB | **≈242MB** |
| 텍스트 + 어휘 pruning(96k) | 262.9M | 1,052MB | ≈263MB |

- 파라미터 분해: 비전 416.9M / 임베딩 167.8M / 디코더 100.3M / 텍스트 나머지 101.1M.
- **동적 INT8은 Linear만 양자화**해 embedding·vision이 FP32로 남아 −6%에 그쳤다. 실제 배포는 ONNX Q8 + 비전 제거 + 어휘 pruning이 필요하다.

## 3. EG2 재사용 대비 비용

| 항목 | 값 |
|---|---|
| EG2 텍스트 Q8 | 684MB |
| T5Gemma 2 텍스트 전용 Q8(추정) | 369MB |
| **재사용 시 절약(추정)** | **≈369MB** (T5 텍스트 타워를 로드하지 않음) |

- EG2를 인코더로 재사용하지 않으면 T5Gemma 2 **텍스트 전용 369MB(Q8)** 를 추가로 로드해야 한다.
- 상주가 아니라 **온디맨드**이므로 비용은 "상주 RAM"이 아니라 **콜드 로드 9.4s + 생성 중 RSS 3.7GB(FP32)** 이다.
- Q8·비전 제거 시 생성 중 RSS는 1GB 내외로 낮아질 것으로 추정되나, **실측 전에는 단정하지 않는다**(ONNX export 후 재측정 필요).

## 4. 온디맨드 정책 제안

| 항목 | 제안 |
|---|---|
| 로드 | 첫 요청 시 로드, 이후 유휴 타임아웃까지 유지 |
| 유휴 타임아웃 | **5분** (콜드 로드 9.4s vs RAM 3.7GB 절충) |
| 폴백 | 로드 실패·OOM 시 텍스트 생성 비활성, STT/검색은 계속 |
| 측정 위치 | 로컬 판정, VPS 값은 참고 |

## 5. 결론

- L0 텍스트 인터페이스는 **구현 가능**하나, 현 FP32 구성은 RAM·지연 비용이 크다.
- 다음 단계(ONNX Q8 + 비전 제거 + 어휘 pruning)를 거쳐야 상주 예산에 맞는다.
- C-2.2의 "잃는 것"은 실측으로 확인됐다: **텍스트 전용 369MB(Q8) + 콜드 로드 9.4s**.
