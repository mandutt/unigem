# D1 — H4′ 재검증 (분절 정렬)

- 작성: 2026-11-02
- 대상: Addendum B §B-8
- 사전 선언: 문장 단위 토큰 문자열 시퀀스 완전 일치율 **≥ 99.5%** → PASS
- 데이터: 코퍼스 v2 4,695문장
- 토크나이저: EG2 `f9972ac2` vs T5Gemma 2 `7c38f166`

## 1. 방법

- 각 문장을 두 토크나이저로 인코딩하고 **특수 토큰(`<bos>`, `<eos>`, `<pad>` 등)을 제거**한 뒤 토큰 **문자열 시퀀스**를 비교했다.
- id가 아니라 문자열을 비교한 이유: 어댑터는 연속 hidden을 사용하므로 위치 정렬의 조건은 id 일치가 아니라 **분절 일치**다(Addendum B §B-8).

## 2. 결과

| 항목 | 값 |
|---|---|
| 비교 문장 | **4,695** |
| 완전 일치 | **4,695** |
| 불일치 | **0** |
| 일치율 | **100.0%** |
| 판정 | **H4′ PASS** (기준 ≥99.5%) |

- 추가: id가 다른 공유 토큰 **6,186개**가 코퍼스 v2에 **0회** 등장한다(토큰 문자열 기준). 즉 실제 데이터에서는 id 차이가 전혀 문제되지 않는다.
- 이전 H4 기각(id 1:1)은 목적에 비해 과도하게 엄격한 정의였다. **문자열 기반 id 변환표로 위치 정렬이 성립**한다.

## 3. C3에 대한 함의

- EG2 hidden → T5Gemma 2 어댑터 경로는 **분절 정렬 문제가 없다**(100% 일치).
- 단, hidden 차원(512)과 디코더 hidden(640)의 어댑터 학습, 그리고 G-DATA(학습 데이터)가 별도 선행 조건이다.
- Addendum B에 따라 arm A2/A3는 CP2′ 이후, arm A1(네이티브)은 F5 제품 후보로 B-11 순서에 따라 진행한다.

## 4. 한계

- 코퍼스 v2 도메인(자연문장·식별자·오타)에 한정. 코드·이모지 등 다른 도메인은 미검증.
- 특수 토큰 제거 규칙은 단순 접두/접미 매칭(`<...>`)이다.
