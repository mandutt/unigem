# B1.5-1 — 프로브 v2 (임베딩 테이블 공유)

- 작성: 2026-11-02
- 대상: Addendum A §A-3.2 (F-2 대응)
- 데이터: 코퍼스 v2 4,695문장 / 학습 토큰 129,407 / 어휘 14,789
- 프로브: `h(512) → W(512, bias 없음) → E(262,144×512) 내적 → softmax`
- 시드 3, epoch 3, AdamW lr 1e-3, batch 4096
- 산출물: `logs/B1_5_probe.json`, `train/b15_probe.py`

## 1. 설계 (Addendum F-2 대응)

| 지적 | 조치 |
|---|---|
| 9,166 클래스 선형 헤드를 따로 학습 | **임베딩 테이블 E를 공유**하고 W만 학습(파라미터 512×512) |
| 층별 비교 불가 | 동일 데이터·동일 예산·동일 시드로 l00/l04/last 비교 |
| 비단조(l08<l04) | 수렴 확인(3 epoch, 학습 손실 안정) 후 비교 |
| 토큰 층화 분할 과대평가 | **문장 그룹 단위 분할**(train/val/test), 토큰은 문장 소속 유지 |

## 2. 결과

| 층 | val 정확도 | test 정확도 | 전체어휘 argmax(4,096표본) |
|---|---|---|---|
| `tok_h_l00` | **0.8905** | **0.8856** | 0.9165 |
| `tok_h_l04` | 0.8164 | 0.8175 | 0.8301 |
| `tok_h_last` | 0.3949 | 0.4438 | 0.4309 |

- **단조 감소** 확인(l00 > l04 >> last). B1에서 보였던 l08<l04 비단조는 재현되지 않았다.
- 절대값이 B1(l00 99.57%)보다 낮은 이유: (a) 어휘가 14,789로 커짐, (b) 코퍼스 v2에 식별자·오타·숫자가 포함되어 난도 상승, (c) 임베딩 테이블 공유로 헤드 자유도 축소.

## 3. 해석

- **l00·l04의 높은 복원률**은 EG2 하위 층이 토큰 정체성을 강하게 보존함을 뜻한다. 복사 충실도(B1.5-4) 전제가 성립한다.
- **last는 44%** — 의미 압축이 진행되어 토큰 단위 복원이 어렵다. F4(맞춤법)에서 원문 보존이 필요하면 l00/l04를 써야 한다는 근거다.
- 전체어휘 argmax가 부분집합보다 높게 나온 것은 **표본이 다르기 때문**(4,096 무작위 vs 전체 test)이며, 동일 표본 비교가 아니다.

## 4. 한계

1. 시드 3회(계획 5회) — 5회로 확장 필요.
2. 전체어휘 argmax는 4,096 토큰 표본만 측정(비용).
3. 층별 정규화(LayerNorm) 전후 비교 미실시.
4. 식별자 span 정확도는 별도 평가 필요(토큰 정확도와 다름).

## 5. 판정

**G-B1.5-a 잠정 PASS** — 층별 단조성과 하위 층 복원력이 확인됐다. 다만 시드 5회·정규화 비교 후 확정한다.
