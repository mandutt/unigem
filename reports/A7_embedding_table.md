# A-7.3 — 텍스트 Q8 텐서 크기 분석 (임베딩 테이블 가설)

- 작성: 2026-11-02
- 대상: Addendum A §A-7.3 (F-10)
- 입력: `onnx/eg2_text_prod_q8.onnx` (+`_data` 679MB)
- 방법: `onnx.load(load_external_data=False)`로 initializer별 external length 집계

## 1. 결과 (상위 텐서)

| 크기 | 텐서 |
|---|---|
| **536.9 MB** | `tm.embed_tokens.weight` (FP32, 양자화 제외) |
| 6.3 MB | `val_69_Q8` |
| 1.0 MB × 다수 | Q8 가중치 블록 |
| 기타 | … |

- 전체 679.2MB 중 **임베딩 테이블이 536.9MB(79.0%)**.
- 가설(F-10) **확인**: Q8 파일의 대부분은 양자화되지 않은 입력 임베딩 테이블이다.

## 2. 함의

- 텍스트 Q8의 실질 연산 가중치는 약 142MB에 불과하다.
- 임베딩 테이블을 FP16/INT8로 줄이면 파일 크기와 로드 시간이 크게 감소할 수 있다.
  단, 입력 임베딩은 출력 품질과 직결되므로 **pooled cosine ≥0.999, 층별 ≥0.998** 검증이 필요하다.
- 다음 실험(제안, 아직 미실행):
  1. 테이블 FP16 저장 + Cast
  2. INT8 행 단위 양자화 + Dequantize
  3. 검증: pooled/층별 cosine, LID 220클립 재실행, 크기·로드·RSS
- 기존 운영·Q8 산출물은 건드리지 않고 새 파일로만 만든다.

## 3. 판정

측정·분석 항목이므로 게이트 판정 없음. F-10 가설 확인 완료.
