## 1. 총평

Addendum D는 CP-C1을 **"제품 경로 = 기존 komixv2/whisper, D = 연구 트랙"** 으로 분리해 기존 논쟁을 정리했다. 이 분리는 논리적이다.

- 인제스트에는 이미 komixv2·whisper-turbo 런타임이 있고, F2는 배치성이며 whisper q4_k는 453MB다. D가 제품 경로가 아니면 "단일 상주" 압박도 사라진다.
- D-γ(운영 그래프 merge) 불허, D-γ′(LoRA 사본) 보류, D-δ(증류) 보류도 비용·위험 기준에서 일관된다.
- D-β 4-arm 파일럿(F-D/F-A/F-B/F-C)은 "LM·projection 병목" 가설을 분해하는 좋은 설계다.
- AM-9(test 1회 사용)·AM-10(arm 동일 조건)은 기존 peeking 문제를 직접 보완한다.
- VPS 5대를 독립 arm에 배분하는 방식은 분산 학습 없이 재현성을 지키는 현실적 선택이다.

다만 **D0-a의 전제가 수치 라벨 오독**이고, **F-A 특징 정의가 가설과 맞지 않는다.** 이 두 건은 실행 전에 고쳐야 한다.

## 2. 검증한 사실

### 2.1 D0-a "정규화 불일치"는 실제로는 라벨 뒤바뀜이다

Addendum D는 이렇게 적었다.

> Notesoop 공백 무시 CER 17.41% → 18.96% (상승), 공백 포함 19.10% → 16.93% (하락) — 방향이 직관과 반대

실제 보고서와 재계산은 반대다.

| 조건 | 구 정규화(Notesoop `normalize_text`) | 신 정규화(C-8 `norm`) |
|---|---|---|
| **공백 포함 CER** | **17.410%** | **16.933%** |
| **공백 무시 CER** | **19.097%** | **18.959%** |

- 구 보고서(`docs/STT/reports/C2_A1_cer.md`)의 `CER 17.41%`는 **공백 포함**, `CER(공백 제거) 19.10%`는 **공백 무시**다.
- 신 보고서(`docs/STT/reports/C8_c2a1_cer.md`)의 `CER(공백 무시) 18.96%`, `CER(공백 포함) 16.93%`와 정확히 같은 방향이다.
- 즉 **"공백 무시가 17.41→18.96으로 상승"이 아니라, 19.10→18.96으로 소폭 하락**했다. 공백 포함도 17.41→16.93으로 하락했다.
- 새 정규화는 두 지표를 모두 **0.14~0.48%p 개선**한다. 직관과 반대되는 현상은 없다.

**재현:** `logs/C2_A1/fleurs_pred.jsonl` 382건에 두 정규화를 적용해 `jiwer.cer`로 계산하면 위 값이 나온다.

**조치:** D0-a는 "원인 규명"이 아니라 **"라벨 오기 정정 + 정규화 코드 단일화"** 로 축소한다. `eval/normalize.py`를 만들고 C-8 규칙을 상수 한 곳에 고정한 뒤, 기존 표의 라벨만 바로잡으면 된다. 3단계 켜고 끄기 실험은 불필요하다.

### 2.2 A2 Q8 다중 출력 그래프는 D-5.4 특징을 모두 제공한다

`onnx/eg2_audio_q8_layers.onnx`를 실제 ORT로 실행해 확인했다.

| 출력 | shape (T=1600 입력) | 의미 |
|---|---|---|
| `audio_features` | `[400, 512]` | `embed_audio` 1536→512 투영 후 |
| `aud_h_l00`~`aud_h_l11` | `[1, 400, 1024]` 각각 | 12층 hidden |
| `aud_out_proj` | `[1, 400, 1536]` | output_proj 후, `embed_audio` **이전** |

- D-5.4의 F-B(11층), F-C(6/8/10/11 혼합)는 이 그래프로 바로 가능하다.
- static shape 메타데이터는 hidden 출력에 없지만, 런타임 shape는 위와 같다. 코드에서 `[1,T,1024]`로 처리하면 된다.
- 운영 LID 그래프 복사본은 C-7에서 11층·output_proj·512 투영 3개만 탭했다. 6/8/10층 탭은 **아직 확인되지 않았다**. D-β 파일럿은 A2 Q8 그래프로 가능하므로, 6/8/10 탭은 **최종 단일 세션 배포 단계(D0-e)** 에서 확인하면 된다.

### 2.3 저장량 계산은 맞다

- 25Hz × 3,600s × 1,024d × 2B × 4층 = **0.737GB/h** (F-C).
- 6h → **4.4GB**, 50h → **36.9GB**. 로컬 48GB, VPS 데이터 예산 약 5GB와 일치한다.
- F-A 512d 6h = 0.55GB, F-B 1024d 6h = 1.1GB, F-D 256d 6h = 0.28GB. D-5.9의 호스트별 수치와 대체로 맞다.

### 2.4 G-A3S 보완 필요

`docs/STT/reports/G_C2a.md`에는 코사인 **평균 0.999642, 최소 0.989480**(30클립)만 있다. Addendum D가 요구한 **프레임별 최소·p1·p5**는 없다.

- Q8 기준 ≥0.98은 최소 0.98948로 통과하지만, 프레임 단위 p1/p5를 봐야 저분위 이상치를 알 수 있다.
- G-C2a 승인 자체는 유지할 수 있으나, **G-A3S 보완 보고 전에는 "특징 충실도 완전 확인"이라고 쓰지 말아야 한다.**

## 3. 수정이 필요한 항목

### P0-1. D0-a의 전제를 정정하라

- 위 §2.1대로 **17.41은 공백 포함, 19.10은 공백 무시**다.
- D0-a를 "정규화 불일치 규명"으로 두면 존재하지 않는 현상을 쫓게 된다.
- **수정:** D0-a를 "정규화 라벨 정정 + `eval/normalize.py` 단일화 + 기존 표 재계산"으로 바꾼다.
- **산출물:** `reports/D0a_normalization.md`에는 "이상 없음, 라벨 오기 정정"을 기록한다.

### P0-2. F-A 특징을 `aud_out_proj`로 바꾸거나 이름을 정확히 하라

D-5.4는 F-A를 이렇게 정의했다.

> 타워 최종 출력 `audio_features` (LM 이전) — LM·projection 병목 제거 효과

그러나 `audio_features`는 **`embed_audio` 1536→512 투영 후** 값이다(`onnx/export_audio.py` §15). LM은 bypass하지만 **projection 병목은 bypass하지 못한다.**

- F-A가 `audio_features` 512라면, F-D(256) 대비 개선은 "LM + 256d MRL 절단 제거" 효과로 해석해야 한다.
- "LM·projection 병목 제거"를 검증하려면 **`aud_out_proj` 1536**을 써야 한다.
- **수정안:** F-A를 `aud_out_proj` 1536으로 교체하고, `audio_features` 512는 Wave 2 ablation(F-A512)으로 둔다.
- 저장량은 1536d 기준 **0.28GB/h**(6h 1.7GB)로, VPS-1 여유에 들어간다.

### P0-3. F-B/F-C의 Q8 hidden parity를 먼저 확인하라

D-5.4는 "Q8 특징 안전성은 G-C2a로 확인"이라고 했지만, G-C2a가 검증한 것은 **최종 256d 특징** 하나뿐이다. F-B(11층 1024d), F-C(6/8/10/11층 1024d)의 **중간 hidden Q8 오차**는 아직 측정되지 않았다.

- C-7은 운영 LID 그래프의 `audio_features`가 원본과 비트 단위 동일함을 확인했지만, 이는 **최종 출력**의 동일성이지 hidden의 FP32 대비 충실도가 아니다.
- Q8 hidden이 FP32와 크게 다르면, F-B/F-C의 결과는 "층 정보"가 아니라 "양자화 잡음"을 반영할 수 있다.
- **수정:** D0-e에서 `eg2_audio_research_fp32_t1600_l12.onnx`와 `eg2_audio_q8_layers.onnx`의 6/8/10/11층 hidden을 같은 입력 20~50개로 비교해 **cos 최소·p1·p5**를 보고한다. 기준 미달이면 F-B/F-C는 FP32 특징으로 먼저 파일럿하고, Q8은 별도 arm으로 둔다.

### P1-1. "10h급 파일럿"과 "4~6h"를 하나로 확정하라

- D-1 표: "10h급 파일럿 → 학습곡선 외삽"
- D-5.3: "4h ≤ H ≤ 6h"
- 두 값이 다르다. F-C 6h가 4.4GB이므로, VPS 데이터 예산 5GB에서는 **H=6h가 상한**이다.
- **수정:** 1차 파일럿은 **H=6h**(또는 5h)로 고정하고, "10h급"은 Wave 2 스케일업 표현으로만 쓴다. 40h 외삽은 학습이 아니라 **곡선 외삽**임을 명시한다.

### P1-2. R-D1 "20% 지지"가 G-C2 15%를 의미하지 않는다

- F-D 기준 18.96%에서 상대 20% 개선은 **15.17%** 로, 여전히 G-C2(≤15%) 위다.
- R-D1은 "병목 가설 지지"일 뿐, G-C2 통과가 아니다.
- **수정:** R-D1 문구에 "G-C2 통과 아님, 스케일업 판단은 R-D2"를 명시한다. 또는 "지지" 기준을 21~25%로 올려 G-C2 근접성을 더 직접 반영한다. 어느 쪽이든 **사전 선언**으로 고정해야 한다.

### P1-3. VPS 메모리·디스크 리스크를 먼저 측정하라

- `vps-3` F-C 6h는 4.4GB. VPS 데이터 예산 약 5GB에서 venv·모델·로그를 빼면 여유가 작다.
- A1(T5Gemma 2) FP32 RSS는 로컬에서 **3,733MB**였다. VPS 6.5GB 상한에서 LoRA 학습(그래디언트·옵티마이저·activation)이 들어가는지 **D-6.1 probe 전에는 단정할 수 없다.**
- **수정:** D0-c/D0-d에서 `vps-3`의 실제 `df`, `vps-5`의 학습 peak RSS를 먼저 재고, 필요하면 H를 5h로 낮추거나 A1을 로컬로 옮긴다.

### P1-4. F4 정상 identity 데이터는 이미 일부 있다

- `data/p1/p1_corpus.jsonl`에는 **clean train 1,600 / clean test 700**이 있다(`is_error=False`).
- D-6.2의 "정상 identity 쌍 약 2,000"을 새로 수집할 필요는 없다. clean train 1,600을 identity 학습에, clean test 700을 과교정 평가(≥600)에 쓰면 된다.
- 단, F4-v2의 2,000문장 확대(D-049)와 혼동하지 말 것. **기존 P1 split을 재사용하고, 새 평가셋과 중복 검사**를 먼저 한다.

### P2-1. D-7.1 라벨링 시트는 HTML로 통일하라

- Addendum D는 "CSV 또는 단일 HTML"로 열어 두었다.
- 사용자는 이전에 **"시트를 html 형태로 만들어줘. csv는 보기 어렵다"** 고 지시했다.
- **수정:** C-9/C2-A2 시트는 **HTML 카드형 + localStorage + JSON 내보내기**로 만든다. CSV는 내부 백업용으로만.

## 5. 채택 시 즉시 해야 할 기록

Addendum D를 채택하면 **측정 전에** 다음을 먼저 기록해야 한다.

1. `docs/addendum_D.md` 저장 + SHA256 계산 → `decisions.md` D-057
2. D-057: CP-C1 결정(F2 제품 = komixv2/whisper, D = 연구 트랙), G-C2a 승인, D-γ 불허, D-γ′/D-δ 보류
3. `gates.md`: AM-9(평가 세트 사용), AM-10(병렬 arm), R-D1/R-D2 사전 선언
4. G-A3S 보완 항목(프레임별 min/p1/p5)
5. `eval/normalize.py` 단일화 및 기존 CER 표 라벨 정정
6. D0-a~D0-e 산출물 경로 확정

**이 기록 전에는 D-5 학습을 시작하지 않는다.**

## 6. 권고

- **Addendum D의 방향은 채택한다.** F2 제품/연구 분리는 기존 프로젝트 목표와 충돌하지 않고, D-β 파일럿은 정보 가치가 높다.
- **단, P0-1(D0-a 라벨 정정)과 P0-2(F-A 특징)를 먼저 반영한 "Addendum D errata"를 만든 뒤** D-057을 기록한다.
- Wave 0는 다음 순서가 좋다.
  1. D0-a 라벨 정정·`eval/normalize.py`
  2. D0-e A2 Q8 출력 확인(이미 상당 부분 확인됨) + G-A3S p1/p5
  3. D0-c VPS 5대 기동·디스크/대역 측정
  4. D0-d 비용 probe
  5. D0-b 다운스트림 지표
  6. D-7 HTML 시트
- D-β는 **F-A를 `aud_out_proj`로 바꾼 4-arm**으로 시작하고, F-A512는 Wave 2 ablation으로 둔다.
- D-γ′는 Addendum D대로 **보류**한다. D-5 결과와 +325MB 비용 견적이 나온 뒤 CP-D1에서 재승인한다.
