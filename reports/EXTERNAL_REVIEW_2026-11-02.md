## 0. 한 줄 요약과 현재 상태

EmbeddingGemma 2(EG2)를 메모리 시스템의 상주 인코더로 재사용해 F1(언어판정)·F2(한국어 STT)·F3(비전 태깅)·F4(맞춤법)·F5(요약)·F6(STT 후처리)을 **별도 대형 모델 없이** 수행할 수 있는지 실측하는 프로젝트다.

- Phase A(ONNX 다중 출력화)와 Phase V(VPS 5대)는 통과했다.
- Phase B1.5에서 **텍스트 hidden의 표면 보존(G-B1.5-a)과 문맥 가치(G-B1.5-b)가 모두 FAIL**했다.
- Q8 견고성(G-B1.5-c)만 PASS다.
- 이 결과로 **CP2(Phase C 진입 전 사용자 결정)**가 열렸고, 사용자는 외부 검토를 먼저 받기로 했다.

## 1. 프로젝트 개요

### 1.1 왜 EG2를 재사용하는가

- 대상 PC: Windows 11, Ryzen 5 7600(6C/12T), RAM **15.6GB**, **GPU 없음**.
- 용도별 특화 모델(언어판정기, STT, 비전 태거, 맞춤법 검사기, 요약기)을 각각 상주시키면 RAM이 부족하다.
- EG2는 이미 메모리 시스템의 임베딩 모델로 **항상 상주**한다. 이 모델의 중간 표현(hidden)을 재사용하면 추가 모델 없이 기능을 늘릴 수 있다는 가설이 출발점이다.

### 1.2 EG2 구조 (실측 확인)

| 구성 | 값 |
|---|---|
| 텍스트 백본 | hidden **512**, **24층**, 양방향 |
| 토큰 임베딩 테이블 | 262,144 × 512 (FP32 536.9MB) |
| 비전 타워 | 16층, hidden 768, patch 16, pooler 3 |
| 오디오 타워 | 12층(층별 hidden 1024), out_proj 1536 → 512 soft token |
| 출력 | `sentence_embedding` 768, 토큰 hidden 512 |

### 1.3 목표 기능

| # | 기능 | 접근 |
|---|---|---|
| F1 | 오디오 언어 판정 | 기존 운영(프로토타입 + margin). 회귀 방지 대상 |
| F2 | 한국어 STT 초벌 전사 | 동결 EG2 + CTC reader(Notesoop 평가 우선) |
| F3 | 비전 태깅 | 화면 → 유사 이모지 검색 → 명칭 태그 |
| F4 | 맞춤법 검사·교정 | 규칙 + 디코더 후보 재순위/편집 태깅 |
| F5 | 메모리 요약 | 디코더 생성 + 슬롯 보존 검증기 |
| F6 | STT 후처리 | CTC 출력 → 디코더 교정 |

### 1.4 설계 원칙

- 하나의 상주 인코더 + 작업별 경량 헤드.
- 디코더는 온디맨드(수 초 지연 허용), 모든 헤드는 폴백 보유.
- 새 경로는 기준선과 같은 데이터·같은 지표로 비교해 이길 때만 채택.
- 성능 판정은 **로컬 PC만** 인정, VPS는 참고.

6. **B1.5 결과**: G-B1.5-a/b FAIL, G-B1.5-c PASS.

### 3.2 주요 함정과 교훈

| 함정 | 내용 | 교훈 |
|---|---|---|
| legacy export | `autograd_inlining=False`로도 `Tensor.unfold` 미추적 | legacy 경로 포기 |
| dynamo export | `dynamic_axes` 사용 시 7~17분 무출력 | **정적 shape + `optimize=False`** |
| ONNX optimizer | Clip 상수 삭제로 ORT 로드 실패(`mul_10_min_1 is not a graph input`) | export 시 optimizer 끔 |
| VPS lock 불일치 | eg2-1에 이전 venv 잔존(43줄 vs 41줄) | `FORCE_REBUILD=1`로 전 머신 재구성 |
| B1 프로브 | 토큰 층화 분할 = 과대평가, 문장 분할 = 미등장 클래스 | 그룹 분할 + 임베딩 테이블 공유로 재설계 |
| l00 의미 | "임베딩 출력"인지 확인 필요 | layer0 출력임을 cosine 0.99998로 확인 |

## 6. Phase B1 상세 — 왜 재설계했는가

### 6.1 결과

- 코퍼스 1,050문장, 8층 캐시, 9,166 클래스 선형 헤드
- 토큰 복원: l00 **99.57%**, l04 94.51%, l08 80.47%, last 69.86%
- 식별자 span exact: l00 **95.5%**, l04 85.3%, l08 52.0%, last 78.0%

### 6.2 설계 결함 6건 (Addendum A F-1~F-6)

1. **F-1**: l00이 순수 임베딩이면 복원은 룩업 역함수라 당연히 높다. 그런데 동일 토큰의 문맥 간 cosine이 0.869 → 순수 임베딩이 아닐 수 있음. → B1.5-0에서 layer0 출력 확인(cos 0.99998).
2. **F-2**: 9,166 클래스 헤드를 2.6만 토큰으로 학습(클래스당 3~4개). 토큰 층화 분할은 과대평가, 문장 그룹 분할은 미등장 클래스로 과소평가. → 임베딩 테이블 공유 + 그룹 분할.
3. **F-3**: G-A3L 불일치가 연구용 FP32에서 났고, 교체 후보 Q8은 44/44. n=44에서 99%는 무오류만 통과 → 220클립 재측정.
4. **F-4**: 식별자 토큰이 n=0이라 계산 불가. span 재정의가 결과를 본 뒤 이루어짐 → 신규 홀드아웃 필요.
5. **F-5**: 게이트에 최소 표본·신뢰구간 규칙 없음 → AM-3.
6. **F-6**: 슬롯 보존율·과교정률 정의가 측정 전 고정되지 않음 → AM-4.

## 9. 사안별 상세 — 배경·실측·쟁점·질문

### 사안 1. G-B1.5-a(표면 보존 98%) 기준이 과도한가

**배경**
- G-B1.5-a는 "EG2 hidden이 원문 토큰을 그대로 복원할 수 있는가"를 측정한다. F4(맞춤법)에서 원문 보존이 안 되면 교정 결과가 원문을 훼손하고, F5(요약)에서 슬롯을 복사할 수 없다.
- 기준 98%는 B1(9,166 클래스, l00 99.57%)을 참고해 설정됐다.

**실측**
- B1.5는 난도를 올렸다: 어휘 14,789(식별자·오타·숫자 포함), 임베딩 테이블 공유(헤드 자유도 축소), 문장 그룹 분할(미등장 토큰 존재).
- 결과 l00 0.8856, l04 0.8175. **−9.4%p / −16.3%p** 미달.

**왜 문제인가**
- 기준을 낮추면 게이트 사후 변경 금지 원칙에 위배된다.
- 반대로 "B1과 B1.5의 난도가 다르다"는 이유로 기준을 유지하는 것도 비교 가능성을 흔든다.
- 식별자 span exact는 별도로 측정하지 않았다(프로브 디코딩으로 계산 가능하나 시간 부족).

**질문**
1. 98%를 유지하고 FAIL로 확정해야 하는가?
2. 아니면 "전체 토큰 정확도" 대신 "식별자·숫자 span exact" 중심으로 재정의하는 것이 정당한가?
3. 재정의한다면 사후 변경 절차(사용자 승인·기록)는 어떻게 해야 하는가?

### 사안 2. G-B1.5-b 판정과 T3 천장 효과

**배경**
- 규칙: "어떤 층이 BL-1 대비 +3%p 이상이고 부트스트랩 하한 > 0인 과제가 T1~T3 중 2개 이상".
- BL-1은 "l00 주변창"으로, 문맥을 명시적으로 제공하는 강한 기준선이다. 깊은 층이 이것을 못 넘으면 EG2의 문맥화는 가치가 없다는 논리다.

**실측**
- T1 +10.6%p(CI +3.4~+17.3) 통과.
- T2 +1.87%p(CI +1.28~+2.48) — 이득은 유의하나 +3%p 미달.
- T3 BL-1 100%로 천장, l04 99.3% — 비교 무의미.

**왜 문제인가**
- T3의 천장 효과는 **과제 설계 결함**이지 EG2의 능력 부족이 아니다. 합성 템플릿이 너무 쉬웠다.
- T2는 "공백 전부 제거"라는 비현실적 변형이라 실제 띄어쓰기 오류와 분포가 다르다.
- 그럼에도 규칙은 "2/3"을 요구하므로 현 상태는 FAIL이 맞다.

**질문**
1. T3를 실제 한국어 오류 분포(문장 내 일부 띄어쓰기 오류, 되/돼 혼동)로 재설계해 재판정해야 하는가?
2. T2의 변형을 "일부 공백만 제거"로 바꿔 재측정해야 하는가?
3. 재측정 시 +3%p 기준과 다중비교 보정을 어떻게 적용해야 하는가?

### 사안 3. "텍스트 hidden 폐기" 규칙의 적용

**배경**

- 그러나 T1(오타 탐지)은 +10.6%p로 뚜렷한 문맥 이득을 보였다. F4에 한정하면 가치가 있다.

**왜 문제인가**
- 규칙을 문자 그대로 적용하면 F4·F5를 포기해야 한다.
- 부분 채택(F4만)은 사전 등록 위반 소지가 있다.
- 폐기와 부분 채택 사이의 제3안(추가 검증 후 조건부 채택)도 가능하다.

**질문**
1. "폐기"를 전체 텍스트 hidden 사용 중단으로 해석해야 하는가, 아니면 F5 결합만 보류로 해석해야 하는가?
2. F4 한정 채택이 정당화되려면 어떤 추가 증거가 필요한가?
3. CP2에서 사용자 승인으로 규칙을 완화하는 절차가 허용되는가?

### 사안 4. B1.5-4 복사 디코더 수행 가치

**실측**

**질문**

2. 수행한다면 l00/l04 중 어느 층을 입력으로 해야 하는가?
3. 20k 샘플 대신 소규모(2k) 파일럿으로 먼저 가능성을 보는 것이 타당한가?

### 사안 5. G-A3L-R FAIL(98.18%)과 운영 교체

**배경**
- F1(언어판정)은 이미 Q8 ONNX로 운영 중이다. 새 ONNX 출력으로 교체할 때 정확도 회귀가 없어야 한다.
- 사전 기준: argmax 일치율 ≥99%, 확신 오판 증가 0.

**실측**
- 44클립: FP32 43/44(97.7%), Q8 44/44 → G-A3L FAIL.
- 220클립(G-A3L-R): **216/220 = 98.18%**, CI [95.41, 99.50]. 기존 197 / 신규 195 정답, 확신 오판 21→23(+2), McNemar p=0.625.
- 방향: 신규만 정답 1, 기존만 정답 3, 둘 다 오답 22.

**왜 문제인가**
- 99% 기준은 "무오류"를 요구하는 매우 엄격한 기준이다. 220클립에서 98.18%는 통계적으로 99%와 구분되지 않을 수 있으나(CI 상한 99.50), 점추정은 미달.
- 확신 오판이 2건 증가한 것은 운영 리스크다.

**질문**
1. 운영 교체를 보류하는 것이 맞는가?
2. 44클립 Q8 44/44를 근거로 예외를 인정할 수 있는가?
3. 99% 기준을 유지하되 표본을 늘려 재판정하는 것이 타당한가?
